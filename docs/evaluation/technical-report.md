**Design decision:** in a learning app the target kanji is always known, so attempts are *verified* against the target and its look-alikes rather than *recognised* from scratch. This removes the need for a trained CNN and makes every judgement explainable at stroke level (ADR-001).

## 2. Method

### 2.1 Matching
1. Normalise the attempt into a unit box and resample each stroke to 32 points.
2. Build a cost matrix between user strokes and reference strokes: mean point distance (forward or reversed, whichever is smaller) plus a direction term.
3. Find the optimal one-to-one pairing with the **Hungarian algorithm**.
4. **Robust re-alignment:** fit a least-squares similarity transform (rotation capped at ±20°, scale, translation; 2-D Procrustes) from the paired strokes, excluding outliers (cost > 1.5 × lower median), and re-match. This is repeated 3 times, so one misplaced or missing stroke cannot distort the alignment of the rest.

### 2.2 Classification rules (thresholds in `src/core/config.ts`)

| Error | Rule |
|---|---|
| Count | Unmatched strokes; *merged* if one user stroke fits two joined reference strokes, *split* for the reverse |
| Order | Strokes outside the longest increasing subsequence of the stroke pairing |
| Direction | Reversed fit beats forward fit by > 0.06 |
| Position | Centroid offset > 0.12 (minor) / > 0.22 (major) |
| Proportion | Smoothed length differs by > 35 % and > 0.08 of the box |
| Ending | Pen only: speed and pressure profile of the last 15 % vs the KanjiVG stroke type (advisory, minor) |
| Confusion | A look-alike's score beats the target's by > 0.02 |

When a stroke-count error is present, position and proportion feedback is withheld, because it becomes unreliable (prioritised feedback).

### 2.3 Evaluation design
No public dataset labels *kinds* of kanji writing errors, so mistakes were **generated with known labels**:
- For every N5 kanji, KanjiVG reference strokes get one injected error: swap two strokes, reverse a stroke, delete / split a stroke, scale a stroke ×0.45 or ×1.7, shift a stroke 0.18–0.30, or substitute a look-alike kanji.
- Human-like noise is then applied (±15 % scale, ±5° rotation, ±0.05 shift, per-point jitter).
- 20 variants per kanji × injector, with a fixed random seed (reproducible).
- **Thresholds were tuned on half the kanji and are reported on the other, unseen half.**

## 3. Results

### 3.1 Error detection, held-out kanji (7,680 attempts)

| Error type | n | Precision | Recall | F1 |
|---|---|---|---|---|
| Stroke order | 1000 | 99.2 % | 100.0 % | **0.996** |
| Direction | 1020 | 100.0 % | 99.5 % | **0.998** |
| Stroke count | 1980 | 100.0 % | 95.8 % | **0.978** |
| Proportion | 960 | 100.0 % | 96.1 % | **0.980** |
| Position | 960 | 98.4 % | 95.3 % | **0.968** |
| Look-alike confusion | 740 | 88.1 % | 100.0 % | **0.937** |

- **False positives on correct attempts: 0.0 %** (1,020 clean attempts).
- **Speed:** 95th-percentile analysis time 3.9 ms per attempt in Node (target + up to 8 look-alikes); NFR target < 30 ms.
- **Tuning vs held-out halves differ by ≤ 0.03 F1**, so the thresholds are not overfitted to particular kanji.

**Reading the confusion-precision figure.** 89 of the "false" confusions come from deleted strokes (e.g. 三 missing a stroke *is* 二). In those cases "you wrote 二" is arguably the more useful feedback, so the true precision for unintended confusions is higher than 88 %.

### 3.1b Robustness to messier handwriting (`npm run robustness`, [robustness.md](robustness.md))
All noise components (scale, rotation, shift, jitter) were multiplied by 0.5–4× on held-out kanji.

| Noise | Macro F1 | False alarms on correct writing |
|---|---|---|
| 1× (main results) | 0.979 | 0.0 % |
| 2× | 0.975 | 0.0 % |
| 3× (±45 % scale, ±15° tilt) | 0.968 | 0.0 % |
| 4× (±60 % scale, ±20° tilt) | 0.936 | 8.8 % |

The first sweep exposed a weakness: at 3× noise, **15 % of correct attempts were flagged**. Isolating each noise component showed the causes: whole-kanji **tilt** (alignment corrected size and position but not rotation → false *position* errors) and **jitter** (inflated stroke length → false *proportion* errors). Two fixes followed: rotation in the alignment (capped at ±20° so it cannot hide a misplaced stroke), and stroke length measured on a coarse 9-point path. Result: false alarms at 3× fell **15.2 % → 0 %**, and at 4× **39.2 % → 8.8 %**. Main-result F1 improved for 5 of 6 types; position dipped 0.974 → 0.968, because rotation correction absorbs a little of a shifted stroke's offset.

### 3.4 Defects found by testing (and fixed)
- FSRS stability and difficulty were stored as 32-bit floats, so they drifted on every sync (found by the live round-trip test).
- The result vanished when an attempt promoted the guide level (found by the live two-device test).
- A second device did not rebuild per-kanji progress or mix-up pairs from synced attempts.
- The school grade was displayed as "[object Object]" (found from screenshots).
- Six colour-contrast failures against WCAG AA (found by the accessibility audit).
- False alarms on tilted or shaky (but correct) writing (found by the robustness sweep): fixed with rotation-aware alignment and jitter-tolerant length.

## 4. Limitations and threats to validity

1. **Synthetic errors are not real handwriting.** Real learners make several errors at once, write unevenly, and use screenless tablets. Real-data accuracy is the key remaining measurement. The pipeline is ready: Export → `scripts/import-fixtures.ts` → label → `npm run evaluate`.
2. **The reference glyphs are KanjiVG's.** Legitimate variant forms (e.g. different 木 hooks) may be flagged. The thresholds are tolerant, and ending checks are advisory only.
3. **Scope is limited to JLPT N5 (103 kanji).** Look-alike detection uses a curated + computed list that includes 26 non-N5 distractors. A confusion with a kanji outside that list is reported as shape errors instead.
4. **The learning-effect claim is not yet tested.** Study mode and the report script exist; the study itself (§7.5 of the plan) has not been run.
